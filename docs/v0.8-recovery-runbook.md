# v0.8 scoped offline recovery

v0.8 adds a conservative recovery command and a repeatable isolated synthetic drill. No schema change or external service is introduced. The v0.7 host setup still applies, but its statement that reconciliation is wholly manual is superseded by this procedure.

## Safety contract

Stop the application AND expiry timer/service, and confirm all database writers are stopped before making or using filesystem copies. Inputs must be regular closed SQLite files in restricted, operator-owned directories. Never copy a live database. Recovery creates a new mode-0700 directory and mode-0600 database, preserves the backup and authority inputs, and never overwrites an existing destination. Keep the destination isolated and unserved throughout recovery. Parent directories must be trusted and have no untrusted symlink or hardlink manipulation.

The authority is the latest intact primary database after all acknowledged deletions, NOT another old backup. The operator must establish its freshness and completeness. The command cannot prove those properties. Each backed-up snapshot survives only if its ID, owner, expiry and encrypted envelope exactly match the authority and its original expiry is strictly later than recovery time. Expired, deleted, missing and changed records are physically removed from the recovered SQLite database with secure-delete and VACUUM. All retained envelopes must authenticate with the supplied key or recovery fails and removes its newly created output. Current-only records are not imported: this is a deliberately scoped recovery of a selected backup.

The exact seven-day upload expiry is preserved, never renewed. Continue using storage:expire and the existing timer after recovery. Trusted current host time is required. Original backups still contain their original ciphertext: reconciliation does not erase backup media, browser copies or exports.

If current authority is lost or completeness cannot be established, use --discard-all. This drops ALL restored snapshots and blocks inference lifetime reservations conservatively. It does not pretend to recover records from an incomplete deletion history. With authority, counters are merged conservatively using maximum count and maximum expiry, including lifetime reservations, so recovery does not refund known usage. Keep inference disabled.

## Operator procedure

1. Stop all writers. Take a closed-database backup into a restricted directory, record its checksum, and keep its encryption key separately protected. Preserve a separate latest closed primary as authority if it is trustworthy.
2. Run from the verified checkout with Node 24 and installed locked dependencies. Provide SITEWITNESS_STORAGE_KEY through protected environment configuration, never command arguments or history.
3. Run `npm run storage:recover -- /absolute/backup.sqlite /absolute/new-isolated-directory /absolute/current-primary.sqlite`.
4. If authority is unavailable or incomplete, run `npm run storage:recover -- /absolute/backup.sqlite /absolute/new-isolated-directory --discard-all`. A missing or unreadable authority path fails; it never silently falls back.
5. Check exit status and the aggregate retained/discarded counts. No records, keys or tokens are printed. Failures remove only the newly created output directory; pre-existing destinations are rejected.
6. Use CURRENT user hashes and the original key, never restore credentials from the backup era. Before any separately approved deployment, verify owner access, revoked-token denial and wrong-owner denial, run expiry cleanup, and inspect the recovered database while isolated. Do not point a running service at a directory being recovered.
7. Preserve evidence and obtain separate launch authorization. Do not roll back a database blindly.

## Reproducible local drill

Run `npm run test:recovery`. It creates fresh temporary directories with synthetic keys and records, closes and copies the primary, deletes a record after backup, attempts a foreign-owner deletion, advances to an exact seven-day boundary, and recovers into a new directory. It checks the database directly before reads, exact photo payload preservation, owner isolation, unchanged expiry, restart behavior, usage reservations, restrictive modes, and unchanged source bytes. Additional cases cover missing authority/discard-all, wrong key, metadata tampering, self-authority, invalid time and an existing output directory. Temporary drill files are removed in finally blocks. No network or real data is used.

Run the full backend, production smoke, browser and vault suites as well; production smoke includes current-token revocation and photograph restoration after process restart.

## Remaining launch gates

No off-site backup transport, independent deletion ledger, backup media erasure guarantee or disaster recovery with a lost primary has been implemented. Preserving selected snapshots requires a demonstrably complete current authority; otherwise discard all. This scope must be accepted before sensitive pilot use. Off-site recovery, hosted HTTPS, service/timer operation on the target host and personal browser acceptance remain unverified. Real Meta inference, access/billing and model evaluation remain unverified. No deployment, push, spending or Meta calls are part of this change.
